# План миграции портфолио Framer → Next.js

Дата исследования: 14 октября 2026 года. Документ обновлён по мере реализации миграции и визуальной проверки исходных страниц.

## 1. Краткое резюме и границы проекта

Исследованы обе опубликованные одностраничные версии портфолио Романа Титова. На обеих страницах видны вводная карточка, подробный кейс X5 Digital, три кратких записи о предыдущих местах работы, портфолио комиксов и общий набор контактных ссылок. Содержание и локальная графика для X5 в основном представлены парными файлами EN/RU. Начата реализация Next.js в этом проекте; актуальный статус и ограничения проверки приведены в разделе Visual QA.

В рамках миграции предлагается единая страница Next.js с локализованными данными по `/en` и `/ru`, общими структурными компонентами для повторяющихся блоков и отдельными материалами для вводной карточки. До реализации нужно уточнить недостающие материалы и закончить проверку поведения на планшетной ширине и состояний взаимодействия.

Границы этой фазы: только исследование и данный документ. В папке проекта сейчас нет исходников Next.js; видимые пользовательские файлы — brief и каталог `img`. Имеющиеся файлы не изменялись.

## 4. Предлагаемая иерархия компонентов и схема локализации

```text
app/
  [locale]/page.tsx       # /en и /ru
  page.tsx                # переход на /en либо согласованное определение языка
components/
  LanguageSwitch
  ProfileCard
  ContactLinks
  X5CaseStudy
  CaseStudyNarrative
  PhoneGallery
  ProductCardGallery
  ConceptGallery
  ExperienceEntry
  ComicsGallery
  SiteFooter
content/
  en.ts
  ru.ts
```

Предлагается оставить разметку повторяющихся секций общей, а тексты, описания изображений и их локализованные пары хранить отдельно. Содержимое вводной карточки в языках отличается; для неё нужно сохранить оригинальную композицию, выбирая верный локальный слой текста/изображения. Переключатель должен вести на соответствующий язык той же страницы (здесь обе версии одностраничные).

Базовая схема маршрутов brief `/en` и `/ru` подходит: у источника в каждой локализации одна страница. Предлагается корневой `/` перенаправлять на `/en`, если владелец не предпочитает редирект по языку браузера. Языковой редирект пока не подтверждён требованиями исходного поведения.

### Недостающие материалы и неопределённости

- Нет локальных файлов шрифта/иконок; отдельные иконки видны внутри скриншотов приложения, отдельные веб-иконки — в интерфейсе контактов/ссылок.
- Точная связь экранов `iphone11`–`iphone15` с каждой подписью концепт-галереи не подтверждена по доступному дереву. Нужно повторно сверить последовательность на широком и узком экранах.
- Не выяснено, являются ли некоторые снимки мобильного приложения отдельными статическими изображениями или часть контента/подписей накладывается поверх них.
- Шесть локальных обложек комиксов визуально совпадают с шестью работами в исходной галерее; размеры и форматы записаны выше.

## 11. Предлагаемый технический подход и структура маршрутов

- Next.js App Router + TypeScript.
- Маршруты `/en` и `/ru`; это совместимо с brief и соответствует двум версиям одной страницы.
- Корневой `/` по умолчанию перенаправляет на `/en`; определить browser-language redirect только при отдельном согласовании, так как источник — два отдельных домена, а не общий language negotiation.
- Основной CSS — CSS Modules или обычный CSS. Для небольшой страницы без готового проекта CSS Modules дают локальные стили и не требуют utility-зависимости; выбранный вариант зафиксировать перед реализацией.
- Один набор структурных компонентов и два набора локализованных данных. Отдельно обработать вводную карточку и места, где состав контента различается.
- Оригинальные PNG/JPG сохранять. Для сайта использовать уже предоставленные WebP после сравнения визуального качества; не перекодировать исходники повторно без необходимости.
- Простые hover/переходы делать CSS. Motion for React подключать только если исследование подтвердит управляемое/scroll-linked движение, которое сложно точно выразить CSS.
- Семантические ссылки, видимый клавиатурный focus, локализованные `alt`, touch-доступность галерей, `prefers-reduced-motion`.
- Использовать предоставленные обложки комиксов и проверить качество/кроп относительно опубликованной галереи. Не подставлять посторонние изображения.
- Для обнаруживаемости в ChatGPT разрешить `OAI-SearchBot` в `robots.txt` и проверить, что CDN/хостинг не блокирует его запросы. Это делает сайт доступным для поискового краулера, но не гарантирует показ или цитирование: OpenAI указывает, что выдача зависит от разных факторов.
- Не смешивать `OAI-SearchBot` (поиск) и `GPTBot` (возможное использование для обучения): решения по этим краулерам независимы. До выбора владельца предлагаем разрешить поискового бота и явно запретить GPTBot.
- Сформировать `sitemap.xml`, canonical URL для каждой языковой страницы и взаимные `hreflang` для `/en` и `/ru`; отдать локализованный основной текст и metadata в исходном HTML при серверном рендеринге, без требования выполнить клиентский клик.
- Добавить корректные title/description, Open Graph, `lang` на документе и JSON-LD для `Person` с подтверждёнными данными и ссылками на CV/публичные профили. Не добавлять FAQPage/Article/Organization, если это не соответствует реальному содержимому и сущности страницы.
- Оставить `llms.txt` как необязательный экспериментальный файл: статья его рекомендует, но в проверенной официальной инструкции OpenAI условием eligibility является доступность сайта для `OAI-SearchBot`; наличие `llms.txt` не обещает попадание в ответы.
- Тексты портфолио сохранить по исходнику. Не расширять страницу искусственными FAQ или объёмом 1500+ слов только ради следования порогу из статьи: это утверждение статьи не является гарантией индексации ChatGPT и конфликтует с требованием точной миграции. Новые редакционные страницы обсуждать отдельно.

Снять скриншоты ключевых состояний и сравнить геометрию, переносы, кадрирование изображений, фон и отступы. Проверить, что `/robots.txt` не блокирует `OAI-SearchBot`, sitemap перечисляет языковые URL, canonical/hreflang согласованы, metadata и JSON-LD присутствуют в server-rendered HTML, а страница/ассеты отвечают краулеру без логина, CAPTCHA или bot challenge. Текущий источник удалось открыть через браузер, поэтому на финальном шаге нужно повторить сравнения с ним; если автоматические скриншоты источника будут недоступны, указывать ручную сверку и конкретные ограничения.

## 14. Риски, ограничения и вопросы, от которых зависит точность

1. Обложки комиксов теперь присутствуют в `img/compressed` и визуально совпадают с исходной галереей. В каталоге всё ещё нет шрифтов и отдельного видеоконтента.
2. При повторной проверке исходной EN-страницы на 557×781 английская биография отображается на карточке корректно; прежнее сообщение о русском тексте относится к уже исправленному состоянию.
3. Семейства шрифтов сверены с исходным CSS: системный sans-serif, Cinzel, Merriweather и Inter; файлы веб-шрифтов сохранены локально.
4. Точные анимации, scroll-linked состояния и жесты исходника не полностью исследованы. В текущей версии галереи горизонтально прокручиваются touch/trackpad, но точное поведение исходных рядов может отличаться.
5. Для `SITE_URL` требуется задать реальный публичный домен перед публикацией, иначе sitemap не содержит URL, а canonical/hreflang не выводятся.
6. Метка Framer удалена как элемент платформы, не добавлялся бренд Next.js. Это видимое отличие от источника.
7. Разрешение OAI-SearchBot открывает возможность обхода, но не гарантирует, что ChatGPT выберет портфолио для конкретного вопроса или процитирует его. Для упоминаний в ответах важно, чтобы запросы были релевантны содержимому страницы и чтобы сведения о человеке/работах совпадали с публичными источниками.
8. В статье предлагаются llms.txt, Schema.org Article/FAQPage/Organization, FAQ 3–6 вопросов и минимум 1500 слов. Для одностраничного портфолио эти форматы частично не подходят; указанное число слов и наличие FAQ не подтверждены официальной документацией OpenAI как порог допуска или гарантия цитирования.

Вопросы, решённые в переписке:

- `/` перенаправляет на `/en`; переключатель EN/RU открывает начало соответствующей версии.
- Сохраняем исходный контент, не добавляя искусственный FAQ/SEO-страницы; аналитика в первой версии не подключается.
- `OAI-SearchBot` разрешён, `GPTBot` запрещён.

## 16. Обнаруживаемость сайта в ответах ChatGPT

### Выводы из статьи

В статье [vc.ru: «Почему ваш сайт не в ответах ChatGPT, когда конкурент уже там»](https://vc.ru/ai/3035948-pochemu-vash-sayt-ne-viden-v-otvetakh-ii-poiskovikov) предлагается сначала проверить технический доступ, затем структуру и schema-разметку, после этого — контент и измерение. Автор рекомендует `llms.txt`, FAQ, вопросительные заголовки и объём от 1500 слов, а также раздельно отслеживать упоминание бренда и ссылку-цитату.

Эта последовательность полезна как чек-лист, но описанные в статье типы Schema.org и порог в 1500 слов нельзя считать требованиями ChatGPT. Для точной миграции портфолио не нужно превращать существующую страницу в длинную статью или добавлять искусственный FAQ. Технические и структурные улучшения ниже сохраняют исходный контент и внешний вид.

### Практические требования для этого сайта

1. Опубликовать страницы без логина и блокирующих проверок ботов. В `robots.txt` разрешить `OAI-SearchBot` для публичных страниц; отдельно проверить сетевые правила хостинга/CDN. По документации OpenAI, именно `OAI-SearchBot` используется для появления сайтов в ChatGPT Search. Результат не гарантирован.
2. Отдельно выбрать правило для `GPTBot`: он относится к возможному обучению моделей и управляется независимо от `OAI-SearchBot`. Разрешение одного не означает разрешение другого.
3. Отдавать заметный текст, имя, специализацию, кейсы, даты, награды и ссылки в серверном HTML. Не прятать основную биографию/смысл кейсов только в изображении или после взаимодействия.
4. Использовать корректные локали `en`/`ru`, title/description, canonical и парные `hreflang`; добавить sitemap с обеими локализациями.
5. Добавить JSON-LD типа `Person` только с проверенными биографическими фактами, ролью, публичными ссылками `sameAs` и релевантными работами. `Organization`, `Article` и `FAQPage` добавлять лишь при наличии соответствующей сущности/страницы.
6. Не добавлять в точную миграцию новые вопросы/ответы, длинные статьи или невидимые ключевые слова без отдельного согласования. Если цель — отвечать в ChatGPT на более широкие вопросы о UX и продуктовом дизайне, вероятно, понадобятся отдельные редакционные материалы и внешние авторитетные упоминания; это отдельная задача, и даже она не гарантирует цитирование.
7. После публикации проверять техническую доступность сайта для обхода. Аналитика не входит в первую версию и не подключается сейчас. Сохранить возможность добавить её позже отдельной настройкой; UTM-метка в ссылке может использоваться тогда, если владелец решит измерять переходы.

### Проверенные источники

- [Официальный обзор OpenAI Crawlers](https://developers.openai.com/api/docs/bots): назначение OAI-SearchBot/GPTBot, независимость настроек и требование не блокировать OAI-SearchBot для ChatGPT Search.
- [FAQ OpenAI для издателей и разработчиков](https://help.openai.com/en/articles/12627856): любой общедоступный сайт может появиться в ChatGPT Search, а OAI-SearchBot не должен быть заблокирован. Документ также описывает UTM-метку для тех издателей, которые хотят считать переходы; в первой версии проекта аналитика отложена.
- [Поиск в ChatGPT](https://help.openai.com/en/articles/9237897-chatgpt-search): доступность для обхода делает сайт подходящим для поиска, но позиция зависит от множества факторов и не гарантируется.

### Ограничения и следующие визуальные правки

- Секция кейса X5 близка к исходнику по порядку и ширине, но два больших экрана лояльности в исходном Framer-проекте частично перекрываются/связаны с прокруткой, а здесь стоят последовательно. Точная типографика, анимации, поведение исходных лент и некоторые кропы остаются приближениями.
- В папке локальных материалов нет отдельного скриншота панели инструмента для дизайнеров, который виден в исходном кейсе. Его не подменяли выдуманным изображением.
- В исходном Framer внизу закреплён бейдж «Made in Framer»; в переносе его нет.
- Проверка выполнена локально. Production-хостинг, реальный домен, правила CDN и обход опубликованной версии извне не проверялись. Перед публикацией нужно задать настоящий `SITE_URL` и убедиться, что хостинг не блокирует `OAI-SearchBot`. Разрешение обхода делает сайт доступным для ChatGPT Search, но не гарантирует появление или цитирование ответа.
- Аналитика не подключена. Для будущего подключения не требуется менять архитектуру сайта: достаточно выбрать сервис и добавить его настройку отдельно.
